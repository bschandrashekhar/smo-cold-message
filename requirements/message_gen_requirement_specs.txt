# Prospect Outreach Generator — Requirements & Plan

## Overview
Streamlit app that researches prospects, matches them to service offerings and case studies, and generates personalized outreach messages using a specific brand name. 

Note that this is a two-pass workflow: Pass 1 is "Automated research & manual review". Pass 2 is "Generate messages".

## Input description: data.xlsx (that is going to be uploaded from the UI frontend)

### Worksheet Name: "prospects"
### Following columns are expected as inputs from the users end.
| Column | Description | Filled By |
|--------|-------------|-----------|
| First_Name | First name of the prospect.
| Last_Name | Last name of the prospect.
| Designation | Their current designation.
| Company_Name | Name of the company they work at.
| Email | Their current email address.
| City | City of the prospect.
| State | State of the prospect.
| Country | Country of the prospect.
| Industry | Industry of the prospect.
| Sub_Industry | Sub-Industry of the prospect if applicable. -- THIS IS NOT USED AT ALL CURRENTLY
| Website | Company website URL.
| LinkedIn | LinkedIn of the prospect. (Optional, if provided search will use it otherwise it will deduce it on its own)

### Following columns are going to be generated by LLM & the matcher modules that we have already developed seperately.

| Case_Studies | JSON array of matched case studies from Supabase vector search (persisted to be used in Pass 2). To use CaseStudyMatcher module already developed.
| Industry_Client_References | JSON array of top 5 client names from client_references table, matched by industry vertical with geography & technology priority. To use ClientMatcher module already developed.
| Suggested_Brand_Name_to_use | "LendingLogik" or "CloudChillies" — Claude's assessment based on company's industry. To use BrandMatcher module already developed.
| Message_to_send | Personalized 3-paragraph outreach message tailored to the selected brand (to be generated in pass 2).
| Country | Modify this field to use country as "EMEA" for all the countries that are in Middle East, and Africa. This we are doing as we have in our database limited countries to cater to this geography so we are going to have more options while researching case studies and existing clients to present to them.
| Prospect_Technologies | The list of generic technologies that the prospect uses in JSON format, derived from Technology Research as shown below.

### Worksheet Name: "dates"
### Following columns are going to be used for suggesting a tentative meeting date to the prospect in the messaging that is going to be generated in the column "Message_to_send" of worksheet "prospects".
| Column | Description |
|--------|-------------|
| City | City of the visit (must match values in "prospects", column "City").
| State | State location of the visit (must match values in "prospects", column "State").
| Start_Date | Start date of the meeting window for that location.
| End_Date | End date of the meeting window for that location.
Note: 
  1. If there is no worksheet with this name, then we dont have to weave an inperson meeting request in the message being generated i.e. "Message_to_send".
  2. If a prospect's location doesn't match any row in "dates" worksheet, then use generic phrasing ("Please let me know when we can connect") as part of the messaging i.e. "Message_to_send".

## Streamlit App — Two-Pass UI

### Tab 1: Research (Pass 1)
1. User uploads `data.xlsx` (must have "prospects" + optional "dates" worksheets)
2. App validates required columns, shows preview table. 
3. User clicks "Run Research" button on UI.
4. Pipeline runs Steps 1-2:
   - Uses Brand knowledge (one-time, skipped if JSONs exist)
   - Research per company/prospect (with progress bar)
   - Compute columns in "prospects" sheet for Case_Studies, Suggested_Brand_Name_to_use, Industry_Client_References & Country (Only updations to this field)
5. Results shown in preview table
6. Show a "Download" button → `data_output.xlsx`
7. "Message to send" column left blank — user reviews offline first the output of Pass 1

### Offline Review (Part of Pass 1 but taken offline - "human in the loop")
User opens `data_output.xlsx`:
- Check technology research findings for accuracy
- Adjust brand assignments if needed
- Remove low-intent prospects (delete rows or clear Prospect_Technologies)
- Save the file

### Tab 2: Generate Messages (Pass 2)
1. User uploads the reviewed `data_output.xlsx`
2. App shows summary: "15 prospects ready, 5 skipped"
3. Skip logic:
   - Has "Message_to_send" already → skip
   - Empty "Prospect_Technologies" → skip (user removed it)
4. User clicks **"Generate Messages"**
5. Pipeline runs Step 3 with progress bar
6. **Download** button → `data_final.xlsx` with all columns filled

### Tab 3: Settings
- Brand Knowledge Status: shows if brand JSONs exist, last-modified date
- Refresh Brand Knowledge: button to re-scrape both websites
- View Brand Profiles: expandable sections showing current JSON content

## Pipeline Stages

### Step 1 (Pass 1) — Brand Knowledge (one-time, persisted)
- Scrape www.lendinglogik.com and www.cloudchillies.com using Claude with web search
- Extract for each brand: name, services, verticals, tech_stack, tone_and_positioning, target_audience
- Save as `data/brand_lendinglogik.json` and `data/brand_cloudchillies.json`
- On subsequent runs: check if files exist → skip this step entirely
- **Currently used in message generation (Step 3):** only `tone_and_positioning` and `services` fields
- **Not yet used:** `verticals`, `tech_stack`, `target_audience`, `name` (name comes from Excel column instead)
- Tone guidelines captured so generated messages feel authentic to each brand

        def run_serper(query, api_key):
            response = requests.post(
                "https://google.serper.dev/search",
                headers={"X-API-KEY": api_key},
                json={"q": query}
            )
            results = response.json().get("organic", [])
            return "\n".join(
                f"- {r['title']}: {r.get('snippet', '')}"

        def research_technology(Company_Name, Website, SERPER_API_KEY, ANTHROPIC_API_KEY):

            all_snippets = ""

                model="claude-sonnet-4-6",
                max_tokens=1024,
                system=SYSTEM_PROMPT,
                messages=[{
                    "role": "user",
                    "content": f"company_name='{Company_Name}'\n\n{all_snippets}"
                }]
            )

            exec(response.content[0].text, globals())

            TECHNOLOGY_RESEARCH["website"] = Website;
            
            //Update the Cache table

### Step 3 (Pass 2) — Message Generation
Style rules for message generation:
  - Address prospect by first name only (e.g. "Hi Wendy,")
  - Do NOT use hyphens or dashes anywhere in the message
  - Do NOT reference specific compliance standards or regulations by name (e.g. no APRA, SOC2, PCI DSS) — use generic terms like "compliance standards" instead
  - Keep the total message under 150 words — short and punchy, not verbose or flowery
  - Case study references are brand-neutral — no mention of CloudChillies or LendingLogik within the case study citation, but overall message tone matches the selected brand
  - Industry reference client names CAN be mentioned by name (as they are real clients)
  - Two contacts at the same company get different framing based on their role (CTO → tech depth, VP Sales → ROI)

For each record in the input excel sheet 
{
  - Inputs:     
    - Technology research findings (Prospect_Technologies), 
    - Role of the person (Designation),
    - Brand-neutral case studies (Case_Studies), 
    - Matching client names (Industry_Client_References), 
    - Exact brand profile JSON to use (Suggested_Brand_Name_to_use), 
    - City of the Prospect (City),
    - State of the Prospect (State)
    - "dates" sheet (since it is optional, so the messaging will be generated appropriately)

  - Output: 
    - Generate a 4-paragraph message in the selected brand's tone, the para description are below:
    {
      WARM_MESSAGE = "";

      - **Para 1** (to be generated using GenAI):
          - Articulate understanding of the prospect's technological situation — tailored to their role (Designation). 
          - Naturally mention specific technology names found in the research (e.g. Boomi, Snowflake, MuleSoft) — these set up the thread for the following Para 2. 
          - Do not use prospect-specific or proprietary systems (e.g. "NextGen ApplyOnline") 
          - Address by first name only. 
          - Keep it concise (1-2 sentences). 
          - Do NOT cite specific numbers, metrics, or statistics — it should read like a knowledgeable human wrote it, not a data report.

          WARM_MESSAGE = "Para 1"

      - **Para 2** (to be generated using GenAI): 
          - Pick up the specific technology names from Para 1 and weave them into the case study narrative (Using Case_Studies), but only carry over general-purpose/common technologies (e.g. Boomi, Snowflake, MuleSoft, .NET) — NOT prospect-specific or proprietary systems (e.g. "NextGen ApplyOnline") that wouldn't credibly appear in "work we've done for others." 
          
          - If Para 1 mentions Boomi, Para 2 references how we've helped clients with Boomi integration leveraging Salesforce. Reference similar work done for other clients (from case studies, anonymized as "a leading [industry] company"), showing how we solved challenges around those same technologies leveraging Salesforce. 

          - Only reference these Salesforce clouds/products: Service Cloud, Sales Cloud, Non Profit, NPSP, Experience Cloud, Commerce Cloud, Agentforce, LWC, Appexchange Product Development, Marketing Cloud, Pardot, Tableau, CPQ, Data Cloud — do NOT mention any Salesforce products outside this list. If no specific product is a clear match, just say "Salesforce" without naming a specific Salesforce Product. Multiple clouds may be combined if relevant.

          WARM_MESSAGE += "Para 2"

        - **Para 3** (Generated using a fixed template): 
            TEMPLATED_PARA_3 = "Some of our existing clients in similar space such as yours include: ";
            TEMPLATED_PARA_3 += Industry_Client_References; 
            WARM_MESSAGE += TEMPLATED_PARA_3;

            - If ("dates" worksheet is present) {

            } else {
              TEMPLATED_PARA_4 = "It would be really good to discuss this over a brief call. Please let me know when we can connect."
            }
            WARM_MESSAGE += TEMPLATED_PARA_4;          
      Store WARM_MESSAGE in "WARM_MESSAGE" column of the excel sheet;
