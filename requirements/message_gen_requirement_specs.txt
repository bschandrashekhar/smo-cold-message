# Prospect Outreach Generator — Requirements & Plan

## Overview
Streamlit app that researches prospects, matches them to service offerings and case studies, and generates personalized outreach messages using a specific brand name. 

Note that this is a two-pass workflow: Pass 1 is "Automated research & manual review". Pass 2 is "Generate messages".

## Input description: data.xlsx (that is going to be uploaded from the UI frontend)

### Worksheet Name: "prospects"
### Following columns are expected as inputs from the users end.
| Column | Description | Filled By |
|--------|-------------|-----------|
| First_Name | First name of the prospect.
| Last_Name | Last name of the prospect.
| Designation | Their current designation.
| Company_Name | Name of the company they work at.
| Email | Their current email address.
| City | City of the prospect.
| State | State of the prospect.
| Country | Country of the prospect.
| Industry | Industry of the prospect.
| Sub_Industry | Sub-Industry of the prospect if applicable. -- THIS IS NOT USED AT ALL CURRENTLY
| Website | Company website URL.
| LinkedIn | LinkedIn of the prospect. (Optional, if provided search will use it otherwise it will deduce it on its own)

### Following columns are going to be generated by LLM & the matcher modules that we have already developed seperately.
| Research_Summary | 5-6 bullet points of key findings (initiatives, tech signals, job openings). Try to keep it as a crisp summary.
| Research_Summary_Compressed | Compressed form of Research_Summary if we decide to generate the message for this prospect in Pass 2.
| Case_Studies | JSON array of matched case studies from Supabase vector search (persisted to be used in Pass 2). To use CaseStudyMatcher module already developed.
| Industry_Client_References | JSON array of top 5 client names from client_references table, matched by industry vertical with geography & technology priority. To use ClientMatcher module already developed.
| Suggested_Brand_Name_to_use | "LendingLogik" or "CloudChillies" — Claude's assessment based on company's industry. To use BrandMatcher module already developed.
| Intent_Score | Prospect's likelihood of needing our services, rated X/10 based on signals found. This can be made optional, from the front end when uploading the excel sheet.
| Message_to_send | Personalized 3-paragraph outreach message tailored to the selected brand (to be generated in pass 2).
| Country | Modify this field to use country as "EMEA" for all the countries that are in Middle East, and Africa. This we are doing as we have in our database limited countries to cater to this geography so we are going to have more options while researching case studies and existing clients to present to them.
| Prospect_Technologies | The list of comma-separated generic technologies that the prospect uses, it is derived from the Research_Summary field.

### Worksheet Name: "dates"
### Following columns are going to be used for suggesting a tentative meeting date to the prospect in the messaging that is going to be generated in the column "Message_to_send" of worksheet "prospects".
| Column | Description |
|--------|-------------|
| City | City of the visit (must match values in "prospects", column "City").
| State | State location of the visit (must match values in "prospects", column "State").
| Start_Date | Start date of the meeting window for that location.
| End_Date | End date of the meeting window for that location.
Note: 
  1. If there is no worksheet with this name, then we dont have to weave an inperson meeting request in the message being generated i.e. "Message_to_send".
  2. If a prospect's location doesn't match any row in "dates" worksheet, then use generic phrasing ("in the coming weeks") as part of the messaging i.e. "Message_to_send".

## Streamlit App — Two-Pass UI

### Tab 1: Research (Pass 1)
1. User uploads `data.xlsx` (must have "prospects" + optional "dates" worksheets)
2. App validates required columns, shows preview table. Make an UI element to generate or not generate "Intent_Score" column.
3. User clicks "Run Research" button on UI.
4. Pipeline runs Steps 1-2:
   - Uses Brand knowledge (one-time, skipped if JSONs exist)
   - Research per company/prospect (with progress bar)
   - Compute columns in "prospects" sheet for Case_Studies, Suggested_Brand_Name_to_use, Industry_Client_References, Intent_Score (depending on the UI selection for Intent_Score) & Country (Only updations to this field)
5. Results shown in preview table
6. Show a "Download" button → `data_output.xlsx`
7. "Message to send" column left blank — user reviews offline first the output of Pass 1

### Offline Review (Part of Pass 1 but taken offline - "human in the loop")
User opens `data_output.xlsx`:
- Check research summaries for accuracy
- Adjust brand assignments if needed
- Remove low-intent prospects (delete rows or clear Research Summary) - depending on the UI selection for Intent_Score
- Save the file

### Tab 2: Generate Messages (Pass 2)
1. User uploads the reviewed `data_output.xlsx`
2. App shows summary: "15 prospects ready, 5 skipped"
3. Skip logic:
   - Has "Message_to_send" already → skip
   - Empty "Research Summary" → skip (user removed it)
4. User clicks **"Generate Messages"**
5. Pipeline runs Step 3 with progress bar
6. **Download** button → `data_final.xlsx` with all columns filled

### Tab 3: Settings
- Brand Knowledge Status: shows if brand JSONs exist, last-modified date
- Refresh Brand Knowledge: button to re-scrape both websites
- View Brand Profiles: expandable sections showing current JSON content

## Pipeline Stages

### Step 1 (Pass 1) — Brand Knowledge (one-time, persisted)
- Scrape www.lendinglogik.com and www.cloudchillies.com using Claude with web search
- Extract for each brand: name, services, verticals, tech_stack, tone_and_positioning, target_audience
- Save as `data/brand_lendinglogik.json` and `data/brand_cloudchillies.json`
- On subsequent runs: check if files exist → skip this step entirely
- **Currently used in message generation (Step 3):** only `tone_and_positioning` and `services` fields
- **Not yet used:** `verticals`, `tech_stack`, `target_audience`, `name` (name comes from Excel column instead)
- Tone guidelines captured so generated messages feel authentic to each brand

### Step 2 (Pass 1) — Prospect Research
> **Canonical specs for research methodology live in the skill files:**
> - **Company research**: `.claude/skills/company-research/SKILL.md` — search queries, output schema (`COMPANY_RESEARCH` dict), execution steps, source selection rules. DO NOT SEARCH information that is beyond 3 months old for framing `COMPANY_RESEARCH` dict.

> - **Prospect research**: `.claude/skills/prospect-research/SKILL.md` — LinkedIn-first search strategy, output schema (`PROSPECT_RESEARCH` dict), broadening logic, section population rules. DO NOT SEARCH information that is beyond 3 months old for framing `PROSPECT_RESEARCH` dict.


#### Pipeline orchestration (not in skill files — defined here):
- Read uploaded XLSX — "prospects" sheet for prospect list, "dates" sheet for location→date mapping, if the user has indicated to use it.
- Group prospects by company (deduplication — research company once, personalize per prospect)

        Run company research skill → get `COMPANY_RESEARCH` dict. 

        `COMPANY_RESEARCH` dict is stored in the field "Company_research" column.

      else 
      {

### Step 3 (Pass 2) — Message Generation
Style rules for message generation:
  - Address prospect by first name only (e.g. "Hi Wendy,")
  - Do NOT use hyphens or dashes anywhere in the message
  - Do NOT reference specific compliance standards or regulations by name (e.g. no APRA, SOC2, PCI DSS) — use generic terms like "compliance standards" instead
  - Keep the total message under 150 words — short and punchy, not verbose or flowery
  - Case study references are brand-neutral — no mention of CloudChillies or LendingLogik within the case study citation, but overall message tone matches the selected brand
  - Industry reference client names CAN be mentioned by name (as they are real clients)
  - Two contacts at the same company get different framing based on their role (CTO → tech depth, VP Sales → ROI)

For each record in the input excel sheet 
{
    - Inputs: research findings (Research_Summary), brand-neutral case studies (Case_Studies), matching client names (Industry_Client_References), the exact brand profile JSON to use (Suggested_Brand_Name_to_use), date range from "dates" sheet (since it is optional, so the messaging will be generated appropriately)

    - If Research_Summary exceeds 1500 characters, compress it first via Claude (role-aware, preserves key signals, avoids truncation). We do this here so that we unnecesarily dont run it in Pass 1, if we decide not have consider the prospect for the Pass 2 based on manual review. Store this results in column "Research_Summary_Compressed"

    - Use Claude to generate a 4-paragraph message in the selected brand's tone:

      - **Para 1**: Articulate understanding of the prospect's situation — reference a specific initiative or strategic direction, tailored to their role. Naturally mention specific technology names found in the research (e.g. Boomi, Snowflake, NextGen ApplyOnline, MuleSoft) — these set up the thread for Para 2. Address by first name only. Keep it concise (1-2 sentences). Do NOT cite specific numbers, metrics, or statistics — it should read like a knowledgeable human wrote it, not a data report.

      - **Para 2**: Pick up the specific technology names from Para 1 and weave them into the case study narrative, but only carry over general-purpose/common technologies (e.g. Boomi, Snowflake, MuleSoft, .NET) — NOT prospect-specific or proprietary systems (e.g. "NextGen ApplyOnline") that wouldn't credibly appear in "work we've done for others." If Para 1 mentions Boomi, Para 2 references how we've helped clients with Boomi integration leveraging Salesforce. Reference similar work done for other clients (from case studies, anonymized as "a leading [industry] company"), showing how we solved challenges around those same technologies leveraging Salesforce. Only reference these Salesforce clouds/products: Service Cloud, Sales Cloud, Non Profit, NPSP, Experience Cloud, Commerce Cloud, Agentforce, LWC, Appexchange Product Development, Marketing Cloud, Pardot, Tableau, CPQ, Data Cloud — do NOT mention any Salesforce products outside this list. If no specific product is a clear match, just say "Salesforce" without naming a specific Salesforce Product. Multiple clouds may be combined if relevant. Connect to the prospect's needs. 

      - **Para 3**: Then in a SEPARATE sentence, mention ALL industry reference clients by name (e.g. "Some of our clients in this space include Cellulant, GIB, and Verifone."). Do NOT join client names with the work description — keep them apart to stay accurate in the narrative.

      - **Para 4**: 
        - If "dates" worksheet is provided then close with: "It will be really good to discuss this over a brief call between [start date] and [end date]. Please let me know what works best for you." Dates come from the "dates" worksheet, matched by prospect's city.
        - If "dates" worksheet is NOT provided then close with: "It would be really good to discuss this over a brief call. Please let me know when we can connect."
}
