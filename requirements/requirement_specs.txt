# Prospect Outreach Generator — Requirements & Plan

> It connects to the Supabase case study database for vector search.

## Overview
Streamlit app that researches prospects, matches them to service offerings and case studies, and generates personalized outreach messages. Two-pass workflow: research first, review, then generate messages.

## Input: data.xlsx

### Worksheet: "prospects"
| Column | Description | Filled By |
|--------|-------------|-----------|
| Prospect Name | Full name of the prospect | User |
| Designation | Their current designation | User |
| Company Name | Name of the company they work at | User |
| Website | Company website URL | User |
| Location of Prospect | Geographic location of the prospect (city) | User |
| Country | Country of the prospect (used for geography-based client reference matching) | User |
| Research Summary | 3-4 bullet points of key findings (initiatives, tech signals, job openings) | Claude |
| Case Studies | JSON array of matched case studies from Supabase vector search (persisted for Pass 2) | Claude |
| Industry References | JSON array of top 5 client names from client_references table, matched by industry vertical with geography priority | Claude |
| Suggested Brand Name to use | "LendingLogik" or "CloudChillies" — Claude's assessment based on company's industry | Claude |
| Intent Score | Prospect's likelihood of needing our services, rated X/10 based on signals found | Claude |
| Message to send | Personalized 3-paragraph outreach message tailored to the selected brand | Claude |

### Worksheet: "dates"
| Column | Description |
|--------|-------------|
| Location of Prospect | Geographic location (must match values in prospects sheet) |
| Start Date | Start date of the meeting window for that location |
| End Date | End date of the meeting window for that location |

Fallback: If a prospect's location doesn't match any row in "dates", use generic phrasing ("in the coming weeks").

## Streamlit App — Two-Pass UI

### Tab 1: Research (Pass 1)
1. User uploads `data.xlsx` (must have "prospects" + "dates" sheets)
2. App validates required columns, shows preview table
3. User clicks **"Run Research"**
4. Pipeline runs Steps 1-3:
   - Brand knowledge (one-time, skipped if JSONs exist)
   - Research per company/prospect (with progress bar)
   - Case study matching + brand selection + intent scoring
5. Results shown in preview table
6. **Download** button → `data_output.xlsx` with Research Summary, Brand, Intent Score filled
7. "Message to send" column left blank — user reviews offline

### Offline Review
User opens `data_output.xlsx`:
- Check research summaries for accuracy
- Adjust brand assignments if needed
- Remove low-intent prospects (delete rows or clear Research Summary)
- Save the file

### Tab 2: Generate Messages (Pass 2)
1. User uploads the reviewed `data_output.xlsx`
2. App shows summary: "15 prospects ready, 5 skipped"
3. Skip logic:
   - Has "Message to send" already → skip
   - Empty "Research Summary" → skip (user removed it)
   - Empty "Intent Score" → skip (not researched)
4. User clicks **"Generate Messages"**
5. Pipeline runs Step 4 with progress bar
6. **Download** button → `data_final.xlsx` with all columns filled

### Tab 3: Settings
- Brand Knowledge Status: shows if brand JSONs exist, last-modified date
- Refresh Brand Knowledge: button to re-scrape both websites
- View Brand Profiles: expandable sections showing current JSON content

## Pipeline Stages

### Step 1 — Brand Knowledge (one-time, persisted)
- Scrape www.lendinglogik.com and www.cloudchillies.com using Claude with web search
- Extract for each brand: name, services, verticals, tech_stack, tone_and_positioning, target_audience
- Save as `data/brand_lendinglogik.json` and `data/brand_cloudchillies.json`
- On subsequent runs: check if files exist → skip this step entirely
- **Currently used in message generation (Step 4):** only `tone_and_positioning` and `services` fields
- **Not yet used:** `verticals`, `tech_stack`, `target_audience`, `name` (name comes from Excel column instead)
- Tone guidelines captured so generated messages feel authentic to each brand
- Stage 2 (planned, not implemented): vectorize brand profiles into Supabase to retrieve per-prospect brand differentiators, product capabilities, and vertical-specific positioning instead of passing the same generic tone/services to every prospect

### Step 2 — Prospect Research

> **Canonical specs for research methodology live in the skill files:**
> - **Company research**: `.claude/skills/company-research/SKILL.md` — search queries, output schema (`COMPANY_RESEARCH` dict), execution steps, source selection rules
> - **Prospect research**: `.claude/skills/prospect-research/SKILL.md` — LinkedIn-first search strategy, output schema (`PROSPECT_RESEARCH` dict), broadening logic, section population rules
>
> The Python implementation in `prospect_research.py` must follow these skill specs for query lists, output shapes, and data rules. When updating research methodology, update the skill files first, then align the Python code.

#### Pipeline orchestration (not in skill files — defined here):
- Read uploaded XLSX — "prospects" sheet for prospect list, "dates" sheet for location→date mapping
- Group prospects by company (deduplication — research company once, personalize per prospect)
- For each company: run company research skill → get `COMPANY_RESEARCH` dict
- For each prospect within that company: run prospect research skill → get `PROSPECT_RESEARCH` dict
- Output: Overall research findings per prospect is arrived at by appending `COMPANY_RESEARCH` + `PROSPECT_RESEARCH` dict (stored in "Research Summary" column, without the "thinking it aloud" Claude text)
- Two contacts at the same company get different framing based on their role (CTO → tech depth, VP Sales → ROI)

### Step 3 — Matching & Scoring
- **Case study matching**: Build search query from prospect's initiatives + industry + tech signals → call existing Supabase `match_case_studies` RPC + Voyage AI rerank (same DB as meeting_notes_prep)
- **Industry reference clients**: Look up top 5 client names from the `client_references` table in Supabase (curated, non-vectorized). Two-tier matching:
    - **Tier 1**: Exact industry match (e.g. "banking" for a bank). Clients in the prospect's geography sorted first.
    - **Tier 2**: Related industries (e.g. "lending", "financial services" for a bank). Prospect's geography first. Only used if Tier 1 yields fewer than 5 names.
    - Geography is determined from the `Country` column in the input sheet (e.g. "Australia" matches clients with geography "Australia").
    - Prospect's own company is excluded. Each client name appears only once.
- **Brand selection**: Claude picks LendingLogik or CloudChillies based on:
	  - Prospect's industry vertical and type of work needed. As a thumbrule, if the prospect is from Banking, Financial ervices, or Insurance, Lending vertical, then use LendingLogik as the default. For everything else use CloudChillies brandname.
- **Intent scoring**: Claude rates X/10 based on strength of signals (job postings = strong, general initiatives = moderate, no signals = low)

### Step 4 — Message Generation
- Inputs: research findings, matched case studies (brand-neutral), industry references (client names), brand profile JSON, date range from "dates" sheet
- If research summary exceeds 1500 characters, compress it first via Claude (role-aware, preserves key signals, avoids truncation)
- Claude generates 3-paragraph message in the selected brand's tone:
  - **Para 1**: Articulate understanding of the prospect's situation — reference a specific initiative or strategic direction, tailored to their role. Naturally mention specific technology names found in the research (e.g. Boomi, Snowflake, NextGen ApplyOnline, MuleSoft) — these set up the thread for Para 2. Address by first name only. Keep it concise (1-2 sentences). Do NOT cite specific numbers, metrics, or statistics — it should read like a knowledgeable human wrote it, not a data report.
  - **Para 2**: Pick up the specific technology names from Para 1 and weave them into the case study narrative, but only carry over general-purpose/common technologies (e.g. Boomi, Snowflake, MuleSoft) — NOT prospect-specific or proprietary systems (e.g. "NextGen ApplyOnline") that wouldn't credibly appear in "work we've done for others." If Para 1 mentions Boomi, Para 2 references how we've helped clients with Boomi integration leveraging Salesforce. Reference similar work done for other clients (from case studies, anonymized as "a leading [industry] company"), showing how we solved challenges around those same technologies leveraging Salesforce. Only reference these Salesforce clouds/products: Service Cloud, Sales Cloud, Non Profit, NPSP, Experience Cloud, Commerce Cloud, Agentforce, LWC, Appexchange Product Development, Marketing Cloud, Pardot, Tableau, CPQ, Data Cloud — do NOT mention any Salesforce products outside this list. If no specific product is a clear match, just say "Salesforce" without naming a specific Salesforce Product. Multiple clouds may be combined if relevant. Connect to the prospect's needs. Then in a SEPARATE sentence, mention ALL industry reference clients by name (e.g. "Some of our clients in this space include Cellulant, GIB, and Verifone."). Do NOT join client names with the work description — keep them apart to stay accurate in the narrative.
  - **Para 3**: Close with: "It will be really good to discuss this over a brief call between [start date] and [end date]. Please let me know what works best for you." Dates come from the "dates" worksheet, matched by prospect's city.
- Style rules:
  - Address prospect by first name only (e.g. "Hi Wendy,")
  - Do NOT use hyphens or dashes anywhere in the message
  - Do NOT reference specific compliance standards or regulations by name (e.g. no APRA, SOC2, PCI DSS) — use generic terms like "compliance standards" instead
  - Keep the total message under 150 words — short and punchy, not verbose or flowery
  - Case study references are brand-neutral — no mention of CloudChillies or LendingLogik within the case study citation, but overall message tone matches the selected brand
  - Industry reference client names CAN be mentioned by name (they are real clients)

## Re-run Scenarios

| Scenario | What to do |
|----------|-----------|
| New batch of prospects | Upload fresh `data.xlsx` → Tab 1 |
| Re-generate one message | Clear that cell in Excel, re-upload → Tab 2 |
| Change brand for a prospect | Edit brand in Excel, clear message cell, re-upload → Tab 2 |
| Add prospects to existing batch | Add rows with blank Claude columns, upload → Tab 1 |
| Refresh brand knowledge | Tab 3 → Refresh button |

## Technical Details

### Rate Limiting
- Process prospects in batches of 5-10 with small delays between batches
- Prevents Claude web search rate limit issues on large sheets

### Company Deduplication
- Multiple prospects at the same company share company-level research
- Company researched once, then personalized per prospect
- Saves API calls and keeps messaging consistent across contacts at same org

### Cost Estimate
- Per prospect: ~1 web search call (~$0.02) + 1 vector search (free) + 1 synthesis call (~$0.03) ≈ ~$0.05/prospect
- 50-row sheet ≈ ~$2.50

### Dependencies
- Anthropic SDK — Claude with web_search tool
- Voyage AI — embeddings + reranking (connects to existing Supabase case study DB from meeting_notes_prep)
- Supabase — pgvector case study storage (same DB, same `match_case_studies` RPC)
- openpyxl — Excel read/write
- Streamlit — UI framework
